# План реализации программы: Конвертер изображений в Mindcode (Mindustry v160.7)

## 1. Введение и цель проекта

Разработка утилиты (на языке **Python**), которая принимает на вход любое растровое изображение (PNG, JPG, BMP, WEBP), выполняет его интеллектуальную обработку, оптимизацию и генерирует валидный, высокооптимизированный код на языке **Mindcode** (`.mnd`). 

Полученный код предназначен для компиляции и загрузки в логический процессор Mindustry (версия игры: **release build 160.7**) для вывода изображения на экраны:
- **Logic Display** (`@logic-display`): разрешение **80 × 80** пикселей.
- **Large Logic Display** (`@large-logic-display`): разрешение **176 × 176** пикселей.

## 2. Учет документации и правил проекта

Согласно [`rule.md`](file:///c:/Users/max/Desktop/mindustry/rule.md) и [`MINDCODE_DOCUMENTATION.md`](file:///c:/Users/max/Desktop/mindustry/MINDCODE_DOCUMENTATION.md):
1. **Язык вывода:** Код генерируется строго на синтаксисе **Mindcode** (расширение `.mnd`).
2. **Используемые команды отрисовки:**
   - `draw(:clear, r, g, b);` — фоновая заливка;
   - `draw(:col, %RRGGBB);` — установка цвета кисти через HEX-маску (наиболее компактный формат Mindcode);
   - `draw(:rect, x, y, width, height);` — отрисовка залитого прямоугольника;
   - `drawflush(display1);` — выталкивание буфера отрисовки на экран.
3. **Оптимизация компилятора Mindcode:**
   - Добавление прагм `#set goal = size;` и `#set instruction-limit = 1000;` для максимальной компрессии результирующего mlog-кода.

## 3. Критические технические особенности Mindustry 160.7

1. **Координатная сетка экрана:**
   - В Mindustry начало координат `(0, 0)` находится в **левом нижнем углу** дисплея.
   - В большинстве графических форматов и библиотек (Pillow) начало координат `(0, 0)` — в **левом верхнем углу**.
   - Программа должна инвертировать ось Y: `y_display = target_height - y_img - rect_height`.

2. **Ограничение буфера отрисовки процессора (Draw Buffer):**
   - Внутренний буфер процессора Mindustry вмещает до **256 команд рисования** между вызовами `drawflush`.
   - Если отправить больше 256 команд без сброса, более ранние команды буфера теряются.
   - Программа должна автоматически вставлять `drawflush(display1);` каждые 150–200 операций отрисовки.

3. **Лимит инструкций процессора (1000 строк mlog):**
   - Обычные игровые процессоры (Micro, Logic, Hyper) имеют жесткий лимит в **1000 инструкций**.
   - Прямой вывод каждого пикселя `80x80 = 6400` пикселей физически не поместится в один процессор прямым кодом.
   - Программа предусматривает два режима:
     - **Режим «Стандартный процессор» (до 1000 инструкций):** интеллектуальное сжатие, квантование цветов (например, 4–16 цветов) и жадное объединение смежных пикселей в прямоугольники (2D Greedy Meshing), гарантируя укладывание в лимит 1000 инструкций.
     - **Режим «World Processor / High Detail»:** вывод полной детализации без лимита на количество инструкций (для песочниц, карт сценариев или схем с отключенным лимитом).

## 4. Архитектурный конвейер обработки изображения

```
[ Исходное изображение ]
          │
          ▼
1. Загрузка и кадрирование (Aspect Ratio, Fit/Fill/Crop)
          │
          ▼
2. Масштабирование под сетку дисплея (80x80, 176x176 или кастомное)
          │
          ▼
3. Квантование цветов (Color Quantization: K-Means / Median Cut, дизеринг)
          │
          ▼
4. 2D Greedy Meshing (Объединение соседних пикселей в максимальные прямоугольники)
          │
          ▼
5. Группировка по цветам (Минимизация переключений draw(:col, ...))
          │
          ▼
6. Контроль бюджета инструкций (Подгонка под лимит процессора)
          │
          ▼
7. Генерация кода Mindcode (.mnd) с батчингом drawflush
```

### Подробное описание этапов:

1. **Масштабирование и соотношение сторон:**
   - Поддержка сохранения пропорций с заполнением полей выбранным цветом фона или обрезкой.
   - Выбор целевого разрешения (80×80 для Logic Display, 176×176 для Large Display, либо уменьшенные сетки 40×40 / 60×60 для сложных цветных артов, чтобы строго вписаться в 1000 инструкций).

2. **Квантование палитры:**
   - Преобразование миллионов цветов к ограниченной палитре (от 2 до 32 цветов).
   - Опция Floyd-Steinberg дизеринга (для художественных картинок) или чистого постеризирования (для пиксель-артов, логотипов и схем).

3. **2D Greedy Meshing (Жадное объединение):**
   - Базовый алгоритм объединяет одинаковые по цвету соседние пиксели по горизонтали в полосы, а затем склеивает смежные одинаковые полосы по вертикали в большие прямоугольники (`rect`).
   - Это сокращает число примитивов отрисовки в 5–30 раз по сравнению с попиксельным выводом.

4. **Оптимизация команд цвета:**
   - Самый частый цвет заливается на весь экран одной командой `draw(:clear, r, g, b)`.
   - Все остальные прямоугольники группируются по цвету. Цвет устанавливается один раз: `draw(:col, %HEX);`, после чего следуют вызовы `draw(:rect, ...)` для этого цвета без повторных команд цвета.

## 5. Формат генерируемого Mindcode-кода

Пример выходного `.mnd` файла:

```mindcode
#set instruction-limit = 1000;
#set goal = size;

// Очистка дисплея доминантным цветом фона
draw(:clear, 18, 18, 18);

// Группа цвета 1: %FFB000
draw(:col, %FFB000);
draw(:rect, 10, 15, 30, 20);
draw(:rect, 45, 15, 25, 20);

// Группа цвета 2: %FFFFFF
draw(:col, %FFFFFF);
draw(:rect, 20, 50, 40, 10);

// Сброс буфера на дисплей
drawflush(display1);

// Остановка выполнения (картинка статична)
stopProcessor();
```

## 6. Структура проектируемой программы (Python)

Программа будет реализована на **Python** с использованием стандартного GUI **Tkinter** (не требует сложной установки сторонних фреймворков) и библиотеки **Pillow (PIL)**:

- `mindcode_image_converter/`
  - `converter.py` — ядро программы:
    - класс `ImageProcessor` (загрузка, масштабирование, квантование цветов, инверсия Y);
    - класс `GreedyMesher` (алгоритм 2D объединения пикселей в прямоугольники);
    - класс `MindcodeGenerator` (генерация синтаксиса Mindcode, группировка по цветам, батчинг `drawflush`, оценка количества инструкций).
  - `gui.py` — графический интерфейс пользователя:
    - Кнопка загрузки изображения («Обзор...»);
    - Панель предпросмотра: исходное изображение vs пиксельный результат на дисплее;
    - Переключатели:
      - Тип дисплея (`Logic Display 80x80` / `Large Logic Display 176x176`);
      - Лимит процессора (`Обычный процессор (<= 1000 строк)` / `World Processor (без лимита)`);
      - Количество цветов палитры (2, 4, 8, 16, 32);
      - Дизеринг (вкл/выкл);
    - Счетчик получившихся инструкций в реальном времени;
    - Кнопки: «Скопировать Mindcode в буфер обмена» и «Сохранить в .mnd файл».
  - `cli.py` — интерфейс командной строки для быстрой конвертации без GUI (например: `python cli.py input.png -o output.mnd --display small`).
  - `main.py` — точка входа для запуска.
