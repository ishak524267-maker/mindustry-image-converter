# Полное руководство по языку Mindcode и Schemacode

**Mindcode** — это высокоуровневый процедурный язык программирования и оптимизирующий компилятор для логики игры **Mindustry** (Mlog / Mindustry Logic). Он преобразует человекочитаемый структурированный код с переменными, функциями, циклами, массивами и модулями в компактные и высокопроизводительные инструкции ассемблера Mindustry Logic (`mlog`).

**Schemacode** — специализированное расширение поверх Mindcode, предназначенное для декларативного описания полных игровых схем (schematics) Mindustry в текстовом виде с последующей компиляцией в бинарный формат `.msch` или код для буфера обмена.

Репозиторий проекта: [https://github.com/cardillan/mindcode](https://github.com/cardillan/mindcode)  
Официальное веб-приложение: [https://mindcode.herokuapp.com/](https://mindcode.herokuapp.com/)

## 1. Обзор и архитектура

В оригинальном Mindustry процессоры программируются на низкоуровневом ассемблере **mlog**. Ограничение одного микропроцессора составляет максимум **1000 инструкций**, а скорость выполнения варьируется от 120 инструкций в секунду (Micro Processor) до 1500 (Hyper Processor) и десятков тысяч для World Processor.

Программирование сложных алгоритмов на чистом `mlog` сопряжено со сложностями:
- Отсутствие именованных локальных областей видимости.
- Ручная расстановка безусловных и условных переходов (`jump`).
- Сложность реализации рекурсии, вызовов подпрограмм и структур данных.
- Необходимость вручную экономить инструкции и циклы процессора.

**Mindcode** решает эти проблемы:
1. Предоставляет привычный синтаксис (похожий на Ruby, Pascal и Kotlin/Python).
2. Выполняет многопроходную оптимизацию AST и промежуточного кода:
   - Устранение мертвого кода (Dead Code Elimination).
   - Инлайнинг функций (Function Inlining).
   - Раскрутка циклов (Loop Unrolling) и вынос инвариантов (Loop Hoisting).
   - Оптимизация прыжков (Jump Straightening, Jump Threading).
   - Объединение операций печати (Print Merging).
   - Оптимизация конструкций `case` с генерацией таблиц переходов по `@counter`.
3. Поддерживает все версии игры Mindustry: от классической **v6** и **v7** до новейшей **v8 (Build 160.5+)**, поддерживая процессорную параллельность, атомарные секции, новые инструкции работы со строками и цветами.

## 2. Быстрый старт и примеры

### Пример 1. Мониторинг хранилища с выводом на текстовое табло

```mindcode
// Привязываемся к ядру или хранилищу и экрану сообщений
var message = message1;
var container = vault1;

var copper = container.@copper;
var lead = container.@lead;
var titanium = container.@titanium;

println($"=== Склад ресурсов ===");
println($"Медь:      $copper");
println($"Свинец:    $lead");
println($"Титан:     $titanium");
printflush(message);
```

### Пример 2. Автоматическая добыча меди дронами Mono

```mindcode
#set target = 8.2m;
#set syntax = strict;

begin
    // Привязываем юнит типа Mono
    var unit = ubind(@mono);
    if unit != null then
        // Если дрон пуст, ищем медь
        if unit.@totalItems < unit.@itemCapacity then
            var found = ulocate(:ore, :core, false, @copper, out var oreX, out var oreY, out var oreFound, out var building);
            if oreFound then
                ucontrol(:mine, oreX, oreY);
            end;
        else
            // Если полон — несем в ближайшее ядро
            var coreFound = ulocate(:building, :core, false, @copper, out var coreX, out var coreY, out var hasCore, out var core);
            if hasCore then
                ucontrol(:itemDrop, core, unit.@totalItems);
                ucontrol(:approach, coreX, coreY, 3);
            end;
        end;
    end;
end;
```

## 3. Синтаксис и структура программы

### Формат файлов и комментарии

- Исходные файлы Mindcode имеют расширение `.mnd`.
- Инструкции разделяются точкой с запятой `;`. Пробелы, табуляции и переводы строк игнорируются компилятором.
- Однострочные комментарии начинаются с `//`:
  ```mindcode
  // Обычный комментарий
  ```
- Многострочные комментарии заключаются в `/* ... */`:
  ```mindcode
  /* Это блочный
     многострочный комментарий */
  ```
- **Enhanced Comments (расширенные комментарии)** начинаются с `///`:
  ```mindcode
  /// Этот комментарий может попадать в mlog как директива или комментарий
  param RATE = 100; /// Базовая частота опроса
  ```
  Поведение `///` регулируется директивой `#set remarks`.

---

### Режимы синтаксиса: Relaxed, Strict, Mixed

Mindcode поддерживает три режима компиляции (задаются через `#set syntax = <режим>;`):

| Режим | Описание | Особенности |
|---|---|---|
| **`relaxed`** *(по умолчанию)* | Мягкий синтаксис. Подходит для быстрых и компактных скриптов. | Код можно писать прямо на верхнем уровне программы. Переменные можно не объявлять ключевым словом `var`. Область видимости необъявленных переменных определяется соглашением об именовании: переменные, содержащие хотя бы одну строчную букву — **локальные**, только заглавные — **глобальные**. |
| **`strict`** | Строгий режим. Рекомендуется для средних и крупных проектов. | Код верхнего уровня запрещен (весь исполняемый код должен быть внутри блоков `begin ... end`, функций или бесконечных циклов). **Все переменные должны быть явно объявлены** через `var`, `const` или `param`. |
| **`mixed`** | Переходный режим. | Код компилируется по правилам `relaxed`, но любые нарушения стандартов `strict` выводятся в виде предупреждений компилятора (Warnings). |

Пример кода в режиме `strict`:
```mindcode
#set syntax = strict;

const MAX_ITEMS = 500;
var total = 0;

begin
    var current = vault1.@coal;
    if current < MAX_ITEMS then
        total += current;
    end;
    print(total);
    printflush(message1);
end;
```

### Идентификаторы и ключевые слова

- Язык чувствителен к регистру: `if` — ключевое слово, `If` или `IF` — допустимый идентификатор переменной.
- Идентификаторы состоят из латинских букв `a-z`, `A-Z`, цифр `0-9` и символа подчеркивания `_`. Первый символ не может быть цифрой.
- Ключевые слова Mindcode:
  `allocate`, `and`, `atomic`, `begin`, `break`, `cached`, `case`, `const`, `continue`, `debug`, `def`, `descending`, `do`, `else`, `elsif`, `end`, `export`, `external`, `false`, `for`, `guarded`, `heap`, `if`, `in`, `inline`, `internal`, `linked`, `loop`, `mlog`, `module`, `noinit`, `noinline`, `not`, `null`, `or`, `out`, `param`, `private`, `public`, `ref`, `remote`, `require`, `return`, `stack`, `then`, `true`, `var`, `void`, `volatile`, `when`, `while`.
  *(Зарезервированы: `elif`, `elseif`).*

---

### Mlog-ключевые слова

Некоторые инструкции ассемблера Mindustry Logic принимают фиксированные ключевые слова (например, тип локации `:core`, тип сенсора `:building`, режим стрельбы `:shoot` и т.д.).

В Mindcode такие ключевые слова **всегда начинаются с двоеточия** и пишутся в стиле **camelCase**:
```mindcode
ulocate(:building, :core, enemy, out x, out y, out found, out building);
ucontrol(:approach, targetX, targetY, 4);
```
> [!NOTE]
> Mlog-ключевые слова не могут сохраняться в обычные переменные. Их можно использовать только как прямые аргументы встроенных функций, аргументы инлайн-функций либо константы (`const MODE = :building;`).

### Встроенные переменные и константы Mindustry

Все переменные и константы самой игры Mindustry начинаются со знака `@`:
- **Аппаратные / окружение**: `@this` (сам процессор), `@thisx`, `@thisy`, `@counter` (указатель команд), `@ipt` (инструкций за игровой тик), `@links` (число привязанных блоков), `@time` (миллисекунды), `@tick` (игровые тики, 60 в секунду), `@second`, `@minute`, `@mapw`, `@maph`.
- **Юниты**: `@unit` (текущий привязанный юнит), константы типов: `@flare`, `@mono`, `@poly`, `@mega`, `@horizon`, `@zenith`, `@alpha`, `@beta`, `@gamma` и т.д.
- **Ресурсы и жидкости**: `@copper`, `@lead`, `@coal`, `@graphite`, `@titanium`, `@thorium`, `@silicon`, `@plastanium`, `@phase-fabric`, `@surge-alloy`, `@water`, `@cryofluid`, `@slag`, `@oil` и т.д.
- **Свойства блоков и юнитов**: `@dead`, `@health`, `@maxHealth`, `@shield`, `@armor`, `@team`, `@shootX`, `@shootY`, `@shooting`, `@mineX`, `@mineY`, `@mining`, `@speed`, `@itemCapacity`, `@totalItems`, `@payloadCount` и др.

### Литералы: числа, цвета, символы, строки

#### 1. Числовые литералы
- **Десятичные целые и вещественные**: `42`, `-15`, `3.14159265`
- **Экспоненциальная запись**: `1e6`, `1.5e-3`
- **Шестнадцатеричные (HEX)**: `0xFF`, `0x10A`, `-0x20`
- **Двоичные (BIN)**: `0b101010`, `0b11110000`

> [!IMPORTANT]
> В Mindustry Logic все вычисления производятся в формате IEEE 754 64-bit float (`double`). Точными для целочисленных и битовых операций являются значения до $2^{53}$ (до 9 007 199 254 740 992).

#### 2. Цветовые литералы
- В формате шестнадцатеричной маски с префиксом `%`:
  - `%RRGGBB`: например, `%FF0000` (красный), `%00FF00` (зеленый), `%0000FF` (синий).
  - `%RRGGBBAA`: например, `%FFFFFF7F` (полупрозрачный белый).
- Именованные цвета (Mindustry 8+): `%[salmon]`, `%[red]`, `%[green]`, `%[gold]`, `%[sky]`.

#### 3. Символьные литералы
- Заключаются в одинарные кавычки: `'A'`, `'z'`, `'\n'`, `'\''`, `'"'`.
- Имеют числовое значение равное их коду ASCII (`'A'` эквивалентно `65`).
- Идеально подходят для инструкции `printchar`:
  ```mindcode
  for ch in 'A' .. 'Z' do
      printchar(ch);
  end;
  ```

#### 4. Строковые литералы и escape-последовательности
- Обычные строки: `"Привет, Mindustry!"`
- Escape-последовательности (в таргетах 8.2+):
  - `\n` — перевод строки
  - `\"` — двойная кавычка
  - `\\` — обратный слэш
  - `\$` — знак доллара
  - `\uXXXX` — 16-битный символ Unicode (например, `\u0020` для пробела)

#### 5. Форматированные строки (String Interpolation)
Строки с префиксом `$` позволяют внедрять значения переменных и выражений:
```mindcode
var item = @surge-alloy;
var count = vault1.sensor(item);
println($"На складе $count шт. ресурса $item (половина: ${count / 2})");
printflush(message1);
```

## 4. Переменные, память и стек

### Области видимости

1. **Глобальная область видимости (Global scope)**:
   - Переменные, объявленные на верхнем уровне программы.
   - Доступны из любой точки программы и функций.
   - Сохраняют свои значения между циклами выполнения процессора (когда указатель доходит до 1000 или вызывается `end()`).

2. **Локальная область видимости (Local scope)**:
   - Переменные внутри функций, блоков `begin ... end` или циклов `for`.
   - Не конфликтуют с одноименными переменными в других функциях.

---

### Модификаторы хранения

Каждая переменная может иметь один из базовых модификаторов хранения:

```mindcode
[модификатор] var имя = значение;
```

1. **`const`** — константа времени компиляции. Не занимает регистров процессора, значения подставляются компилятором напрямую:
   ```mindcode
   const MAX_CAPACITY = 1000;
   const HALF_PI = @pi / 2;
   ```
2. **`param`** — параметр программы. Создает инициализированную переменную в первой строке программы mlog, которую пользователь может менять прямо в игре:
   ```mindcode
   param DESIRED_UNIT = @flare;
   param MIN_COPPER = 500;
   ```
3. **`linked`** — переменная, жестко связанная с блоком, подключенным к процессору:
   ```mindcode
   linked container = vault1;
   linked screen = display1;
   ```
4. **`external`** — переменная хранится не в регистрах процессора, а в ячейке или банке памяти (требует предварительного объявления кучи `allocate heap`):
   ```mindcode
   allocate heap in cell1;
   external counter = 0;
   external status = 1;
   ```
5. **`export`** — переменная процессора, доступная другим процессорам для удаленного чтения/записи (Mindustry 8):
   ```mindcode
   export var globalState = 0;
   ```
6. **`remote`** — переменная, физически расположенная на другом удаленном процессоре:
   ```mindcode
   remote(processor2) var slaveState;
   ```
7. **`debug`** — отладочная переменная. Значения сохраняются в регистры с именами, удобными для чтения во встроенном отладчике.

---

### Дополнительные модификаторы

| Модификатор | Совместимость | Назначение |
|---|---|---|
| **`cached`** | `external`, `remote` | Кеширует значение переменной в локальном регистре процессора. Чтение происходит мгновенно без обращения к шине памяти; запись обновляет и регистр, и внешнюю память. |
| **`guarded`** | `linked` | Генерирует защитную инструкцию ожидания подключения блока: процессор циклится на месте, пока блок не будет физически подсоединен. |
| **`mlog("name")`** | `debug`, `export`, `remote` или обычные | Принудительно задает строковое имя mlog-переменной в результирующем коде (полезно при ручной связке с чужим mlog-кодом). |
| **`noinit`** | `export`, `external`, `linked`, `remote` | Отключает предупреждения о неинициализированной переменной; для `cached` означает «только запись» без начального считывания. |
| **`volatile`** | любые регистры | Запрещает оптимизатору удалять или переупорядочивать чтения/записи переменной (необходимо при параллельном доступе или внешнем сигнале). |

Пример использования модификаторов:
```mindcode
guarded screen = message1;          // Ждет, пока message1 не станет доступен
cached external savedScore = 0;    // Внешняя память с кешированием
volatile mlog("custom_flag") flag; // Точное имя переменной в mlog
```

---

### Выделение кучи (`allocate heap`)

Для автоматического размещения `external` переменных и массивов во внешних ячейках (`@memory-cell`, 64 слота) или банках памяти (`@memory-bank`, 512 слотов) используется директива `allocate heap`:

```mindcode
// Использовать cell1 целиком (индексы 0..63)
allocate heap in cell1;

// Использовать только диапазон ячеек от 10 до 49 в bank1
allocate heap in bank1[10 ... 50];
```

Если количество объявленных `external` переменных превысит емкость выделенной кучи, компилятор выдаст ошибку на этапе сборки.

---

### Выделение стека (`allocate stack`)

Для работы рекурсивных функций компилятору требуется стек вызовов:

1. **Внешний стек (External Stack)** в ячейке или банке памяти:
   ```mindcode
   allocate stack in bank1;
   // или с ограничением по диапазону:
   allocate stack in bank1[256 ... 512];
   ```
2. **Большой стек (Large Stack)**, распределенный по нескольким банкам:
   ```mindcode
   allocate stack in (bank1 .. bank4);
   ```
3. **Внутренний стек (Internal Stack)**:
   Применяется, когда внешняя память отсутствует, а глубина рекурсии невелика. Компилятор использует локальные регистры процессора.

## 5. Массивы (Arrays)

В Mindcode массивы индексируются с нуля `0`. Элемент массива получается с помощью квадратных скобок: `arr[0]`, `arr[i]`.

### Неявные массивы

Любой подключенный блок памяти (`cell1`, `cell2`, `bank1` и т.д.) автоматически является массивом чисел:
```mindcode
cell1[0] = 42;
var val = bank1[105];
```

---

### Внутренние массивы

Внутренние массивы хранятся прямо в регистрах процессора:
```mindcode
var buffer[10];                     // Массив из 10 элементов
var values[] = (10, 20, 30, 40);    // Автоматический размер: 4 элемента
```
- В отличие от ячеек памяти, внутренние массивы могут хранить **любые типы данных**: объекты юнитов, ссылки на здания, строки, предметы и `null`.
- Для произвольного доступа по переменному индексу компилятор генерирует эффективные jump-таблицы по `@counter`. Если индекс известен на этапе компиляции (`buffer[2]`), чтение/запись преобразуется в прямое обращение к переменной без потерь скорости.

---

### Внешние массивы

Размещаются в куче (памяти ячейки или банка):
```mindcode
allocate heap in bank1;

external buffer[100];
buffer[0] = 123.45;
```

---

### Большие массивы (Large Arrays)

Массив, размер которого превышает объем одного банка памяти (512 ячеек), может быть распределен сразу по нескольким банкам:
```mindcode
linked storage = (bank1, bank2, bank3, bank4);
external(storage) var bigData[2048];
```
Компилятор сам вычисляет нужный банк памяти и смещение внутри него.

---

### Динамические массивы

Встроенные неизменяемые массивы, отражающие окружение Mindustry:
- `links` — массив всех подключенных к процессору блоков.
- `items` — массив всех типов предметов в игре.
- `liquids` — массив всех типов жидкостей.
- `unitTypes` — массив всех типов юнитов.
- `blocks` — массив всех игровых типов блоков.
- `teams` — доступные команды.

Функция `length(array)` возвращает текущую длину массива:
```mindcode
for var i in 0 ... length(links) do
    var block = links[i];
    println($"Блок $i: $block");
end;
printflush(message1);
```

---

### Срезы массивов (Subarrays)

Срезы позволяют выбрать диапазон элементов массива без создания копии:
```mindcode
var data[10];
var part1 = data[0 .. 4];   // Включая индекс 4 (5 элементов)
var part2 = data[5 ... 10]; // Исключая индекс 10 (5 элементов)
```

---

### Массивы подстановки (Lookup Arrays)

В Mindustry 8+ компилятор умеет создавать сверхоперативные таблицы поиска через модификатор `mlog(:type)`:
```mindcode
mlog(:item) var itemPrices[itemCount];
```

## 6. Выражения и операторы

### Таблица приоритетов операторов

Операторы перечислены в порядке убывания приоритета (от наивысшего к наинизшему):

| Приоритет | Операторы | Тип / Ассоциативность | Описание |
|---|---|---|---|
| 1 | `++`, `--` | Постфиксные (левая) | Постинкремент, постдекремент |
| 2 | `++`, `--`, `+`, `-`, `~`, `!`, `not` | Префиксные унарные (правая) | Преинкремент, унарный плюс/минус, побитовое НЕ, логическое НЕ |
| 3 | `**` | Бинарный (правая) | Возведение в степень |
| 4 | `*`, `/`, `\`, `%` | Бинарные мультипликативные (левая) | Умножение, деление, целочисленное деление, остаток |
| 5 | `+`, `-` | Бинарные аддитивные (левая) | Сложение (и конкатенация строк), вычитание |
| 6 | `<<`, `>>` | Сдвиговые (левая) | Побитовый сдвиг влево и вправо |
| 7 | `&` | Побитовое И (левая) | Битовая конъюнкция |
| 8 | `^` | Побитовое ИСКЛ-ИЛИ (левая) | Побитовый XOR |
| 9 | `\|` | Побитовое ИЛИ (левая) | Битовая дизъюнкция |
| 10 | `in`, `not in` | Принадлежность (левая) | Проверка вхождения в диапазон или список |
| 11 | `<`, `<=`, `>`, `>=` | Реляционные (левая) | Меньше, меньше или равно, больше, больше или равно |
| 12 | `==`, `!=` | Нестрогое равенство (левая) | Равенство / неравенство по значению |
| 13 | `===`, `!==` | Строгое равенство (левая) | Равенство / неравенство с проверкой типа |
| 14 | `&&`, `and` | Логическое И (левая) | Короткозамкнутая конъюнкция |
| 15 | `\|\|`, `or` | Логическое ИЛИ (левая) | Короткозамкнутая дизъюнкция |
| 16 | `? :` | Тернарный (правая) | Условное выражение `условие ? да : нет` |
| 17 | `=`, `+=`, `-=`, `*=`, `/=`, `\=`, `%=`, `**=`, `<<=`, `>>=`, `&=`, `^=`, `\|=` | Присваивания (правая) | Простое и комбинированные присваивания |

---

### Арифметические и побитовые операции

```mindcode
var a = 17;
var b = 5;

var sum = a + b;       // 22
var diff = a - b;      // 12
var prod = a * b;      // 85
var quot = a / b;      // 3.4
var intDiv = a \ b;    // 3 (целочисленное деление!)
var rem = a % b;       // 2 (остаток от деления)
var pow = 2 ** 8;      // 256

var bits = (0b1010 & 0b1100) | 0b0001; // 0b1001
var shifted = 1 << 4;                  // 16
```

---

### Операторы принадлежности `in` и диапазоны

- Две точки `..` задают **включающий** диапазон (inclusive): `1 .. 5` (числа 1, 2, 3, 4, 5).
- Три точки `...` задают **исключающий** диапазон (exclusive): `1 ... 5` (числа 1, 2, 3, 4).

```mindcode
if x in 0 ... 100 then
    println("X находится в диапазоне от 0 до 99");
end;

if item in (@copper, @lead, @titanium) then
    println("Это базовый конструкционный металл");
end;
```

---

### Обычное и строгое равенство (`==` vs `===`)

В стандартном mlog команда `jump equal` не различает число `0`, булево `false` и значение `null`, а также `1` и `true`:
```mindcode
0 == false  // true в mlog!
0 == null   // true в mlog!
```
Для устранения подобных ошибок Mindcode вводит **строгое равенство `===` и `!==`**:
```mindcode
null === false  // false!
0 === null      // false!
@copper === 1   // false!
```

---

### Short-circuit вычисления

Логические операторы `&&` (`and`) и `||` (`or`) выполняются по короткой схеме (short-circuit):
```mindcode
// Если unit == null, свойство @dead не опрашивается и ошибка не возникает
if unit != null and not unit.@dead then
    ucontrol(:move, 100, 100);
end;
```

## 7. Управляющие конструкции (Control Flow)

### Условные ветвления: `if` и `case`

#### 1. Оператор `if ... elsif ... else ... end`
```mindcode
if health < 20 then
    println("Критическое состояние!");
elsif health < 60 then
    println("Средний уровень прочности.");
else
    println("Броня в норме.");
end;
```

`if` также может возвращать значение как выражение:
```mindcode
var state = if switch1.@enabled then "Включено" else "Выключено" end;
```

#### 2. Конструкция `case ... when ... then ... end`
```mindcode
case item
    when @copper, @lead then
        color = %FF8800;
    when @titanium then
        color = %0088FF;
    when @thorium then
        color = %FF00FF;
    else
        color = %FFFFFF;
end;
```

И как выражение:
```mindcode
var weight = case block.@type
    when @duo then 1
    when @cyclone then 4
    when @foreshadow then 10
    else 0
end;
```

---

### Циклы: `while`, `do-while`, `loop`

```mindcode
// Цикл с предусловием
while vault1.@coal > 0 do
    generator1.enabled = true;
end;

// Цикл с постусловием
do
    var count = vault1.@silicon;
loop while count < 100;

// Бесконечный цикл
loop
    println("Работаем...");
    printflush(message1);
end;
```

---

### Циклы итерации `for ... in`

#### 1. Итерация по диапазону
```mindcode
for i in 0 ... 10 do
    println($"Индекс: $i");
end;
```

#### 2. Итерация по массиву или списку
```mindcode
for resource in (@copper, @lead, @graphite) do
    var amount = core.sensor(resource);
    println($"$resource: $amount");
end;
```

#### 3. Итерация в обратном порядке (`descending`)
```mindcode
for i in descending 0 .. 5 do
    print(i); // Выведет: 543210
end;
```

#### 4. Параллельная итерация по нескольким спискам
```mindcode
var items = (@copper, @lead, @silicon);
var limits = (1000, 800, 500);

for item, limit in items, limits do
    if vault1.sensor(item) < limit then
        println($"Дефицит ресурса: $item");
    end;
end;
```

---

### C-style циклы `for`

```mindcode
for var i = 0; i < 64; i += 2 do
    cell1[i] = 0;
end;
```

---

### Управление переходами: `break`, `continue`, метки

Операторы `break` и `continue` поддерживают именованные метки для выхода из вложенных циклов:

```mindcode
outer: for x in 0 ... 10 do
    for y in 0 ... 10 do
        if checkHazard(x, y) then
            break outer; // Выход сразу из двух циклов
        end;
    end;
end outer;
```

---

### Блоки кода `begin ... end` и завершение программы `end()`

- Блок `begin ... end` объединяет последовательность инструкций и задает локальную область видимости переменных.
- Встроенная функция `end()` сбрасывает указатель команд процессора `@counter` на нулевую инструкцию (начало программы).
- Функция `stopProcessor()` останавливает процессор до следующего ручного перезапуска или триггера (компилируется в mlog-инструкцию `stop`).
- Функция `stop()` — это команда управления юнитом (`ucontrol stop`), она не останавливает сам процессор.

## 8. Функции

### Объявление и типы параметров (`in`, `out`, `ref`)

Функции объявляются ключевым словом `def`:
```mindcode
def имя_функции(параметр1, out параметр2, ref параметр3)
    // Тело функции
    return результат;
end;
```

Режимы передачи параметров:
- **`in` (по умолчанию)**: передача значения аргумента внутрь функции.
- **`out`**: выходной параметр. Функция записывает в него значение, которое возвращается вызывающей стороне:
  ```mindcode
  def getCoordinates(out x, out y)
      x = @thisx;
      y = @thisy;
  end;

  getCoordinates(out myX, out myY);
  ```
- **`ref`**: ссылка (in/out). Аргумент передается внутрь, может изменяться и возвращается обратно:
  ```mindcode
  def clamp(ref value, minVal, maxVal)
      if value < minVal then value = minVal;
      elsif value > maxVal then value = maxVal;
      end;
  end;

  clamp(ref currentSpeed, 0, 100);
  ```

---

### Возврат значений (`return`)

```mindcode
def max(a, b)
    if a > b then
        return a;
    else
        return b;
    end;
end;

var best = max(10, 25);
```

---

### Модификаторы функций

1. **`inline`** — указывает компилятору встраивать тело функции в место каждого вызова вместо генерации переходов по меткам. Увеличивает скорость исполнения ценой расхода инструкций:
   ```mindcode
   inline def square(x) = x * x;
   ```
2. **`noinline`** — запрещает компилятору встраивать функцию, даже если она вызывается всего один раз.
3. **`atomic`** — тело функции исполняется строго атомарно (без переключения потоков Mindustry 8).

---

### Vararg-функции

Функции с переменным числом аргументов (могут быть только `inline`):
```mindcode
inline def printAll(args...)
    for arg in args do
        print(arg);
        print(" ");
    end;
    println();
end;

printAll("X:", 10, "Y:", 20, "Status:", true);
```

---

### Рекурсия и организация стека

Mindcode поддерживает рекурсивные вызовы функций. Для сохранения локальных переменных и адресов возврата требуется стек:

```mindcode
#set target = 8.2m;
allocate stack in cell1;

def factorial(n)
    if n <= 1 then
        return 1;
    else
        return n * factorial(n - 1);
    end;
end;

println($"5! = ${factorial(5)}");
printflush(message1);
```

---

### Встроенные системные функции

#### Вывод текста и форматирование:
- `print(args...)` — буферизация текста.
- `println(args...)` — печать текста с последующим добавлением перевода строки `\n`.
- `printchar(asciiCode)` — вывод одиночного символа по коду (включая кавычки: `printchar('"')`).
- `printf(format, args...)` — подстановка во время выполнения через маркеры `{0}`, `{1}` (Mindustry 8+).
- `format(args...)` — низкоуровневая инструкция форматирования.
- `printflush(messageBlock)` — сброс буфера на дисплей сообщений.

#### Утилиты и интроспекция:
- `ascii(charString)` — возвращает числовой ASCII код первого символа.
- `char(code)` — преобразует числовой код в строку из одного символа.
- `length(collection)` — возвращает длину массива или системного списка.
- `strlen(str)` — возвращает длину строки в символах.
- `remark("...")` — добавление комментария/отметки в выходной mlog.
- `error("...")` — генерация ошибки компиляции или выполнения.

## 9. Справочник Mindustry Logic API в Mindcode

Mindcode предоставляет полный доступ ко всем инструкциям Mindustry Logic в виде интуитивно понятных функций.

### Управление юнитами

```mindcode
// 1. Привязка юнита нужного типа
var unit = ubind(@flare);

// 2. Базовые команды управления
ucontrol(:idle);                          // Холостой ход
ucontrol(:stop);                          // Полная остановка
ucontrol(:move, x, y);                    // Движение в координаты (x, y)
ucontrol(:approach, x, y, radius);        // Приближение на расстояние radius
ucontrol(:boost, true);                   // Включение ускорения / форсажа
ucontrol(:pathfind, x, y);                // Автопоиск пути к точке
ucontrol(:target, targetX, targetY, shoot); // Наведение оружия
ucontrol(:targetp, enemyUnit, shoot);     // Упреждающая стрельба по цели
ucontrol(:itemDrop, building, amount);    // Сброс ресурсов в блок
ucontrol(:itemTake, building, item, amount); // Взятие ресурсов из блока
ucontrol(:mine, oreX, oreY);              // Добыча ресурса
ucontrol(:flag, number);                  // Установка числового флага юнита
ucontrol(:build, x, y, blockType, rotation, config); // Строительство блока
ucontrol(:getBlock, x, y, out type, out building, out floor); // Считывание блока на карте
ucontrol(:unbind);                        // Отвязка юнита

// 3. Радар юнита
uradar(:enemy, :flying, :any, :distance, 0, 1, out target);

// 4. Поиск объектов на карте
// Находит вражеские ядра, союзные строения, руду и т.д.
ulocate(:ore, :core, false, @copper, out outX, out outY, out found, out building);
ulocate(:building, :core, enemy, @copper, out outX, out outY, out found, out building);
ulocate(:spawn, :core, false, @copper, out outX, out outY, out found, out building);
ulocate(:damaged, :core, false, @copper, out outX, out outY, out found, out building);
```

### Сенсоры и свойства

Для считывания параметров блоков и юнитов можно использовать стандартную функцию `sensor` или синтаксис доступа через точку `.`:

```mindcode
// Через точку:
var hp = vault1.@health;
var maxHp = vault1.@maxHealth;
var isDead = unit.@dead;
var curItem = unit.@firstItem;

// Через sensor():
var copperAmount = sensor(vault1, @copper);
```

Запись свойств (включение/отключение блоков):
```mindcode
switch1.enabled = false;
block.enabled = true;
```

### Память и ввод-вывод

```mindcode
// Чтение и запись ячеек памяти:
write(100, cell1, 0);       // Записать 100 в индекс 0 ячейки cell1
var data = read(cell1, 0);  // Считать из ячейки

// Синтаксис массивов делает то же самое намного красивее:
cell1[0] = 100;
var data = cell1[0];

// Mindustry 8+: чтение и запись блоков текста
writeChars(cell1, offset, "Hello, World!");
readChars(cell1, offset, out myString);
```

### Графика и экраны

Управление дисплеями (`@logic-display` 80x80 и `@large-logic-display` 176x176):

```mindcode
// 1. Очистка экрана цветом (R, G, B) от 0 до 255
draw(:clear, 0, 0, 0);

// 2. Установка цвета рисования
draw(:color, 255, 128, 0, 255); // R, G, B, Alpha
draw(:col, %00FF88);            // HEX-маска цвета

draw(:line, x1, y1, x2, y2);
draw(:rect, x, y, width, height);
draw(:lineRect, x, y, width, height);
draw(:poly, centerX, centerY, sides, radius);
draw(:triangle, x1, y1, x2, y2, x3, y3);
draw(:image, x, y, @copper, size, rotation);

// 5. Трансформации (Mindustry 8+)
draw(:translate, dx, dy);
draw(:scale, sx, sy);
draw(:rotate, degrees);
draw(:reset);

// 6. Сброс буфера на дисплей
drawflush(display1);
```

- `setblock(:floor, @water, x, y);`

## 10. Параллельное программирование и Mindustry 8 Logic

В Mindustry 8 процессоры выполняются в общем пуле квантов времени. Mindcode предоставляет средства для многопроцессорных систем.

### Модули (`module`) и экспорт (`export`)

Модуль определяет набор функций и переменных, запускаемых на отдельном процессоре-исполнителе:

**Файл модуля `DroneWorker.mnd`:**
```mindcode
module DroneWorker;

export var tasksCompleted = 0;

export def mineResource(oreType)
    var u = ubind(@mono);
    if u != null then
        ulocate(:ore, :core, false, oreType, out x, out y, out found, out b);
        if found then
            ucontrol(:mine, x, y);
            tasksCompleted++;
            return true;
        end;
    end;
    return false;
end;
```

---

### Удаленный вызов процедур (RPC)

**Основной процессор:**
```mindcode
require "DroneWorker.mnd";

// Привязываем физический процессор к модулю
processor:DroneWorker = processor2;

// 1. Синхронный вызов (текущий процессор ждет завершения):
var success = DroneWorker.mineResource(@copper);

// 2. Асинхронный вызов (запускается параллельно на другом процессоре):
call async DroneWorker.mineResource(@lead);

// Чтение экспортированной переменной удаленного процессора:
var count = DroneWorker.tasksCompleted;
```

---

### Атомарное выполнение кода (`atomic`)

В Mindustry 8 выполнение кода может быть прервано квантованием времени в середине алгоритма, что может привести к гонкам данных (Race Conditions) между несколькими процессорами, разделяющими одну ячейку памяти.

Mindcode предоставляет конструкцию **`atomic`**:
```mindcode
// Атомарный блок гарантирует выполнение без прерывания
atomic begin
    var balance = cell1[0];
    balance += 50;
    cell1[0] = balance;
end;

// Или в виде функции:
atomic def withdrawMoney(amount)
    if cell1[0] >= amount then
        cell1[0] -= amount;
        return true;
    end;
    return false;
end;
```

Компилятор Mindcode рассчитывает время выполнения блока инструкций и перед входом сверяет `@ipt` и остаток тактов, при необходимости выполняя холостое ожидание (`wait 0`), чтобы гарантировать непрерывное выполнение всей секции.

## 11. Директивы компилятора (`#set`, `#setlocal`, `#declare`)

Директивы компилятора настраивают поведение оптимизатора, целевую версию игры и вывод кода.

```mindcode
#set опция = значение;
#setlocal опция = значение; // Действует только в текущем модуле/функции
```

### Основные опции компилятора

| Директива | Значения | Описание |
|---|---|---|
| **`target`** | `7.0`, `7.1`, `8.0`, `8.1`, `8.2`, суффиксы: `m` (micro), `l` (logic), `h` (hyper), `w` (world) | Задает целевую версию игры и тип процессора (например, `8.2m` по умолчанию). |
| **`syntax`** | `relaxed`, `strict`, `mixed` | Режим синтаксических ограничений. |
| **`optimization`** | `none`, `basic`, `advanced`, `experimental` | Уровень оптимизации кода (по умолчанию `experimental`). |
| **`goal`** | `speed`, `size`, `auto` | Цель оптимизации: приоритет скорости (unroll циклов) или компактности (размер mlog). |
| **`symbolic-labels`** | `true`, `false` | Использовать ли символические метки для переходов вместо абсолютных номеров строк mlog. |
| **`remarks`** | `none`, `passive`, `active`, `comments` | Трансляция расширенных комментариев `///` в mlog: `comments` преобразует их в `# комментарии`. |
| **`instruction-limit`**| Число (по умолчанию 1000) | Максимально допустимое количество инструкций. |
| **`boundary-checks`** | `none`, `simple`, `assert` | Генерация проверок выхода за границы массивов. |
| **`error-reporting`** | `none`, `message`, `status`, `trace` | Способ сигнализирования о runtime-ошибках. |
| **`author`** | Строка / список строк | Имя автора программы (помещается в заголовок mlog). |
| **`program-name`** | Строка | Название программы. |
| **`program-version`**| Строка | Версия программы. |

### Директива `#declare` для расширений и модов

Если мод добавляет новые блоки, предметы или переменные, отсутствующие в стандартном Mindustry, их можно зарегистрировать без ожидания новой версии компилятора:
```mindcode
#declare block @my-mod-drill;
#declare item @dark-matter;
#declare variable @custom-stat;
```

## 12. Стандартная системная библиотека (System Library)

Mindcode поставляется со встроенными оптимизированными библиотеками. Они подключаются директивой `require`:

```mindcode
require math;
require units;
require graphics;
require printing;
require arrays;
```

### 1. `require math;` — Математика
- Константы: `PI`, `DEG_TO_RAD`, `RAD_TO_DEG`.
- `distance(x1, y1, x2, y2)` — евклидово расстояние.
- `round(x)`, `frac(x)` — округление и дробная часть числа.
- `sign(x)` — знак числа (-1, 0, 1).
- `lerp(a, b, t)` — линейная интерполяция.
- `avg(args...)`, `sum(args...)` — среднее арифметическое и сумма.
- `median(args...)` — вычисление медианы.
- `log2(x)`, `logn(x, base)` — логарифмы.

### 2. `require units;` — Управление юнитами
- `findFreeUnit(unitType)` — находит свободный дрон без флага.
- `waitForFreeUnit(unitType)` — ждет появления свободного дрона.
- `findClosestUnit(unitType, x, y)` — находит ближайший юнит заданного типа.
- `noControlWithin(radius)` — проверяет, нет ли поблизости игрока, управляющего юнитом вручную.

### 3. `require printing;` — Форматированный вывод
- `formatNumber(n)` — форматирует число с разделением тысяч запятыми (`1,250,000`).
- `printNumber(n)` — сразу выводит число с разделителями в буфер.
- `formatHexNumber(n)` / `formatBinaryNumber(n)` — форматирование в HEX и двоичный вид.

### 4. `require graphics;` — Графические утилиты
- `unpackcolor(packed, out r, out g, out b, out a)` — разбор упакованного цвета.
- `packHsv(h, s, v)` — создание цвета из оттенка, насыщенности и яркости.
- `rotateLeft()`, `rotateRight()`, `flipHorizontal()`, `flipVertical()`, `scaleDisplay()` — матричные преобразования экранов.

### 5. `require arrays;` — Алгоритмы массивов
- `fill(array, value)` — заполнение массива значением.
- `reverse(array)` — переворот элементов массива задом наперед.
- `bubblesort(array)` — сортировка элементов массива.

## 13. Schemacode: Декларативное создание схем

**Schemacode** позволяет описать полную схему базы Mindustry в текстовом виде.

### Структура файла `.schema`

```schemacode
schematic
    name = "Автономный сепаратор";
    description = "Добывает воду, плавит шлак и разделяет на ресурсы";
    tag = "Производство";

    // Размещение блоков:
    // ИмяМетки: @тип-блока at (X, Y) параметры...
    m1: @memory-cell at (0, 0);
    
    // Сортер с направлением и конфигурацией
    s1: @sorter at (1, 0) facing north config @titanium;

    // Линейный массив конвейеров от (0, 1) до (5, 1)
    @armored-conveyor at (0, 1) .. (5, 1) facing east;

    // Узел питания с соединениями
    node: @power-node at (2, 2) connect to (p1, s1);

    // Микропроцессор с внедренным кодом Mindcode
    p1: @micro-processor at (0, 2)
        links to (m1, s1)
        processor
            // Код на языке Mindcode внутри схемы:
            var target = s1.@config;
            m1[0] = target;
            print($"Сортируем: $target");
            printflush(message1);
        end;
end;
```

### Возможности Schemacode
1. **Координаты и сетка**: относительное позиционирование `at (0, 0)`, массивы блоков `at (0, 0) .. (5, 5)`, круговые массивы.
2. **Повороты**: `facing north`, `facing south`, `facing east`, `facing west`.
3. **Конфигурация любых блоков**:
   - Сортеры, заслонки, фильтры: `config @copper`
   - Сообщения: `config "Привет, мир"`
   - Проекторы и мосты: автоматическое связывание `connect to (...)`
4. **Встраивание процессоров**:
   - `processor` — встроенный код на Mindcode или mlog.
   - `links to (...)` — автоматическое подключение блоков к процессору с генерацией имен `cell1`, `vault1` или символических связей.

## 14. Консольный компилятор (CLI) и интеграция с инструментами

После сборки репозитория исполняемый jar-файл находится по адресу `compiler/target/mindcode.jar`. Для запуска доступны скрипты:
- Windows: `bin/mindcode.bat`
- Linux/macOS: `bin/mindcode`

### Основные команды (Actions)

```bash
# 1. Компиляция файла Mindcode в mlog:
mindcode cm input.mnd -o output.mlog

# 2. Компиляция схемы Schemacode в файл .msch:
mindcode cs schematic.txt -o my_schematic.msch

# 3. Декомпиляция mlog в заготовку Mindcode:
mindcode pm input.mlog -o decompiled.mnd

# 4. Декомпиляция схемы .msch в текстовый Schemacode:
mindcode ps my_schematic.msch -o schematic.txt
```

### Полезные флаги командной строки
- `-c`, `--clipboard` — **Копировать результат прямо в буфер обмена**. Идеально для вставки прямо в процессор игры Mindustry!
- `-l <file>`, `--log <file>` — вывод сообщений сборки в лог-файл.
- `-a <file>`, `--append <file>` — подключение дополнительных файлов исходного кода.
- `--target 8.2m` — переопределение целевой платформы.
- `--optimization experimental` — выбор профиля оптимизации.
- `--run` — **запуск скомпилированного кода во встроенном эмуляторе процессора Mindcode** с выводом результатов работы в консоль.

---

### Интеграция с модами

1. **Mlog Watcher**:
   Мод для игры Mindustry, открывающий локальный WebSocket/порт. Компилятор Mindcode может отправлять скомпилированный код или схему прямо в выделенный процессор на запущенной карте Mindustry без ручной вставки через буфер обмена.
2. **Mlog Dev Tools**:
   Мод, добавляющий в Mindustry инструкции для высокопроизводительной проверки выхода за границы массивов, точки останова (breakpoints) и счетчики тактов для профилирования.

## 15. Советы, паттерны и оптимизация (Best Practices)

### 1. Экономия тактов процессора против экономии размера
- Процессор выполняет фиксированное число инструкций за игровой тик (Micro: 2 инстр./тик; Logic: 8 инстр./тик; Hyper: 25 инстр./тик).
- Для критичных к скорости участков (например, прицеливание турелей, управление боевыми дронами) используйте `#set goal = speed;` и инлайн-функции `inline def`.
- Для фоновых задач (сортировка складов, вывод на экраны) используйте `#set goal = size;`, чтобы уложиться в 1000 строк mlog.

### 2. Оптимальная работа с большими массивами
- Обращение по индексу `arr[i]` для внутреннего массива генерирует прыжок по таблице `@counter`.
- Если вам нужно перебрать весь массив, используйте цикл **`for item in arr do`** — компилятор разворачивает его в линейную итерацию без таблиц переходов, что в разы быстрее.

### 3. Безопасная привязка дронов
При совместной игре или работе нескольких процессоров:
```mindcode
// Используйте числовой флаг юнита, чтобы не конфликтовать с чужими процессорами
const MY_FLAG = 77701;

var unit = ubind(@flare);
if unit != null then
    // Если дрон никем не занят (флаг равен 0) или уже наш:
    if unit.@flag == 0 or unit.@flag == MY_FLAG then
        ucontrol(:flag, MY_FLAG);
        // Выполняем задачу...
    end;
end;
```

### 4. Избегайте лишних `printflush` и `drawflush`
- Вызовы `printflush` и `drawflush` очищают буферы процессора и требуют времени. Вызывайте их **один раз в конце цикла вычислений**, а не внутри итераций.
